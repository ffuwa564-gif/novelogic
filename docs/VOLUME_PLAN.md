# 『二人』長編化・文庫100ページ計画 v0.1

> 対象作品：**『二人』**

> 執筆上の仮目標：**約50,000字**。文字数とページ数は一致しないため、**ページ数の達成は実際のPDFで確認**する。  
> 状態：制作計画。分量は執筆しながら改訂してよい。  
> 参照：[プロット](PLOT.md)／[文体品質](STYLE.md)／[メタファー](METAPHORS.md)／[描きたい場面](SCENE_ELEMENTS.md)／[PDF仕様](PDF.md)／[第一幕改稿 v0.2](../drafts/revisions/futari_01_rewrite.md)

## 1. 目標と基本原則

1. **分量の目標**は文庫本100ページ以上。50,000字は実現のための作業目標であって、必要十分な保証ではない。
2. **品質を維持する。** 第一幕改稿 v0.2 のように、自然な会話・少女の仕草・細部から生まれる感情を大切にする。文字数稼ぎの反復・説明・水増しはしない。
3. **増やすのは読者が二人と過ごす時間。** 一場面ごとの欲望、出来事、心情変化を積み重ねる。甘い場面も恐ろしい場面も単調に連発しない。
4. **物語が長くなっても人物は二人だけ。** 第三者や安直な別の恋人を追加して展開を稼がない。
5. **長さを優先して完成稿にしない。** 各幕に欠かせない場面が揃い、全体として読めることを満たしたうえで、最終組版のページ数を調整する。

## 3. 量を増やすための場面設計

### 第一幕：陶酔（13,000字）

今ある髪を結う場面、庭で転ぶ場面、霧の日の涙と再会を核として残す。新規追加候補：

- 二人で少し遠くへ出かける一日。世界にほかの誰もいないことが、孤独ではなく親密さとして感じられる。
- 夕方の光の中でお互いの影を使って遊ぶ、何も起こらない穏やかなひととき。癒しを主目的とし、必要なら後の幕の対照にする。
- リリィと手をつないで買い物をする外出。好みの糸や制作材料を一緒に選び、歩幅を合わせる。**二人以外に人がいない世界**での店の成立方法は、[描写設計](SCENE_ELEMENTS.md)の未決事項として扱う。
- ガラスの花を一輪作るのに失敗し、まったく別の形が生まれる日。リリィの好奇心とクロエの愛情が同時に見える。
- 些細な意見の違いと仲直り。後の激しい関係破綻と対比できる、対等な二人の姿。
- 一緒に眠れない夜。相手を気遣う仕草が、過剰な説明なしに伝わる場面。
- 永遠を約束した日。ただし二人の理解の違いは、その時点で露骨な不穏さにならない。

狙い：読者が後の第三幕で「あのときの二人」を実際の場面として思い出せること。

### 第二幕：倦怠（10,000字）

- 時間の経過は数字による要約だけでなく、習慣、庭の広がり、作りかけのもの、繰り返す季節で示す。
- リリィが「新しい青」などの研究・発見に徐々に夢中になる。ただし好奇心自体は肯定される。
- クロエの待ち時間、返事をもらうまでの間、視線のずれを少しずつ大きくする。
- 「こっちを見て」が、第一幕とは違う切実さを持ちはじめる。
- 二人の言い分にそれぞれ説得力があり、話し合っても簡単には一致しない。

狙い：大事件が唐突な豹変に見えない、因果と時間の厚みを持たせること。

### 第三幕：崩壊（20,000字）

**全幕を束縛する側の少女の視点で語る。** 暴走する行為の数を増やすだけではなく、視点そのものが歪む過程を長い時間をかけて描く。

- 前半：怒りの噴出、髪や糸を通じた境界侵害、拒否される経験、涙への誤った解釈。
- 中盤：幸福な過去を再現しようとする試み、記憶への介入、修復という名目の実験、基準の変質。
- 後半：理想像と実際の少女の区別が薄れる、涙さえ欲する自己矛盾、偽りの完成、破綻。

長い分量の必要性は**同じ行為の反復に見えて毎回何かが失われること**にある。各場面で「何を求めた／何が起きた／どの認識が変わった／被害者に何が残った」を明確にする。被害を装飾にせず、相手の意思が奪われている事実が読者に伝わるようにする。

### 第四幕：余韻（7,000字）

- 事件の鎮静や変化は具体的な行動として描く。
- 幸福と悲劇のどちらにも読める根拠を、本文の中に実際に置く。
- 第一幕と同じ「髪を結ぶ」「目を合わせる」「花を眺める」等の行動を再訪できる。ただし意味を言葉で決めつけない。
- 第三幕から突然元の無垢な二人へ戻さず、傷・記憶・選択の曖昧さに十分な紙幅を割く。

狙い：読み手の解釈が割れても、因果と結末の描写そのものには納得できること。

## 4. 分量を増やすときの品質チェック

各場面に「足す理由」があるか、次の問いで確認する。

- **固有性：** 他の場面と交換できない出来事や観察があるか。
- **関係の変化：** 場面の前と後で、期待・理解・距離のどれかが変わるか。
- **人物の魅力：** 筋書きがなくても、この少女らしい仕草や選択があるか。
- **象徴の自然さ：** 髪・糸・ガラスの花・目が場面に必要なものとして存在するか。
- **余白：** 主題を人物に説明させたり、情景へ無理に比喩を重ねたりしていないか。
- **全体との関係：** 後続で回収するもの、または既出場面を読み替える機能があるか。

上記をすべて機械的に満たさなければならないわけではない。空気を味わう短い場面にも意味はあるが、**内容の薄い場面でページ数を稼がない**こと。

## 5. 実際に文庫100ページになったかの検証

リポジトリの現行設定は [styles/novel.css](../styles/novel.css) に基づく **A6（105 × 148 mm）、縦書き、9pt明朝体、余白 上14mm・左右12mm・下16mm、行間1.85**。[組版ガイド](PDF.md)も参照。

この版面では、単純な字詰め計算による1ページの理論上限はおおむね**数百字（約450〜500字程度）**。ただし実際は句読点・会話の改行・見出し改ページ・空白・ルビによって大きく変動する。**この値から完成ページ数を断定しない。**

1. 原稿を **novels/ 直下のMarkdown** に配置する。現在の第一幕改稿は `drafts/` にあり、そのままでは自動PDF化の対象外。
2. GitHub Actionsの[小説PDFワークフロー](https://github.com/ffuwa564-gif/novelogic/actions/workflows/pdf.yml)を走らせる、またはローカルで `npm ci` → `npm run build` を実行。
3. 生成されたPDFの**総ページ数と本文ページ数を確認**する。タイトル・空白・章扉で100ページになっただけ、という達成を避ける。
4. **目標に足りない場合**は、文字数を水増しするのではなく、因果上必要な場面を充実させる。100ページを超えた場合でも、不要な場面は削る。
5. 本文が完成したら、PDFのページ数、余白、読みやすさをもう一度検証する。印刷所へ入稿する場合はその指定を別途確認する。

## 6. 実行順序

1. 現行の第一幕 v0.2 を品質の基準稿として保存したまま、第一幕の場面を追加する。
2. 第一幕を約13,000字に整え、文体・心理・会話を推敲する。
3. 第二幕の約10,000字で時間の蓄積を描き、第三幕へ至る感情の因果を成立させる。
4. 第三幕の約20,000字で、視点人物の認識の変質を丹念に追う。
5. 第四幕の約7,000字で、多義的だが因果が明確な結末を作る。
6. 全体を通読して重複を削り、正式原稿をPDF化して100ページ以上を実測する。

**作品づくりの原則：** 文字数を増やすのではなく、読者が二人と過ごした時間を増やす。
