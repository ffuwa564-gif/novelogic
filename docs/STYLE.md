# 『二人』文体・執筆品質ガイド v0.1

> **目的**：『二人』の文学的な文章品質を、執筆と推敲の反復で改善する。  
> **状態**：制作ガイド（実験可能・改訂前提）。筋書きや人物像の確定設定ではない。  
> 参照：[プロット](PLOT.md)／[メタファー](METAPHORS.md)／[第一幕の試作](../drafts/futari_01.md)

## 1. 結論：文章専用APIは必須ではない

文章の質を上げるために、最初から専用APIを導入する必要はない。APIは、工程を自動化する段階になったときに検討する。

当面は、**場面設計 → 執筆 → 批評 → 推敲 → 最終審査**を独立した工程として扱う。特定のモデルを選ぶだけで品質が自動的に保証されるわけではない。必要なら複数モデルの文章を匿名比較し、差を検証する。

注意：同じモデルを複数の「役割」として呼んでも、独立した専門家が保証されるわけではない。同じ誤りを見落とすことがある。最終的な採否は作者が判断する。

## 2. 『二人』が目指す文体

| 観点 | 方針 |
| --- | --- |
| 基調 | 静謐・繊細・抑制的。光、手触り、距離、沈黙を丁寧に扱う |
| 語彙 | 正確で自然な日本語を優先。難語や美辞麗句の増量を目標にしない |
| 会話 | 生活に根差した言葉。台詞を思想の説明台にしない |
| 心理 | 行為、知覚、言い淀み、記憶の選択から伝える。説明が必要なら簡潔に |
| 比喩 | 髪、糸、ガラスの花、目。意味を暗号のように固定しない |
| リズム | 長い観察と短い決断、沈黙を対比。単調な文末と文長の連続を避ける |
| 視点 | 視点人物が知りえない心理を地の文で断定しない |
| 時間 | 悠久の長さを「千年が過ぎた」と言うだけで済まさず、行為と細部の変化で感じさせる |
| 不穏さ | 第一幕は自然な幸福が先。のちの崩壊を暗示しようとしすぎない |
| 余韻 | 説明で結論を閉じず、しかし読み取る根拠は本文に残す |

**文学的＝難解な日本語**ではない。読み手の知覚と感情を丁寧に導くことを優先する。

## 3. 現在の試作で見えている課題

対象：[第一幕 v0.1](../drafts/futari_01.md)。

### 課題 A：心理を結果として説明しすぎる

現行例：

> 今日のリリィは、明日の朝もきっとこうして笑うだろう。  
> そう思えることが、何より幸せだった。

この書き方は明瞭だが、読者に判断させる余白が小さい。改稿ではクロエの視線、保存したい瞬間、手を伸ばす／伸ばさないという行動に転換できる。

**比較用の改稿候補（確定稿ではない）：**

> リリィは、色の消えた壁にもう一度花をかざした。  
> クロエは手伝わなかった。  
> 花が動くたび、リリィの頬に別の光が落ちる。そのなかで、いちばんよく笑った顔の角度を、覚えようとしていた。

こちらのほうがよいとは限らない。「顔の角度を覚える」は少し作為的にも読める。読者にどちらが自然で印象に残るかを比較してもらう。

### 課題 B：会話の機能が単純な応答に偏る

「なに？」「うん」「そうだね」の連続だけで会話を運ばない。言葉の選択、話題転換、答えない理由、行動との食い違いを入れる。ただし会話をすべて含蓄のある名台詞にしない。何気ない言葉にも固有の生活感を残す。

### 課題 C：象徴の用途が見えすぎる

「髪は束縛」「花は永遠」と本文で解説せず、たとえば結び目を緩める行為を自然に描く。それが後に結び目を緩めなくなる行為と対になったとき、読者が自分で意味を見つける。

### 課題 D：場面ごとの固有性が薄い

綺麗な背景や優しい台詞を置くだけで終わらない。各場面に**その日にしか起きない出来事**と、少女それぞれの欲望をひとつは置く。

例：リリィには新しい青を見つけたい理由があり、クロエにはその瞬間のリリィの表情を覚えたい理由がある。両者の欲望は第一幕では幸福に共存できる。

### 課題 E：叙述のリズムが一定

連続して「〜だった」「〜した」を積み重ねる単調さ、短文ばかりのぶつ切り、不要な修飾の付け足しを場面単位で点検する。音読で息が詰まる箇所も修正する。

## 4. 一場面を仕上げる五工程

推奨単位は**一場面あたり約800〜1,500字を初期の実験範囲**とする。これは規則ではなく比較のための目安。場面に必要なら短くても長くてもよい。

### ① 構成作家：場面の設計

本文を書く前に、短いシートを作る。

- 場面が始まるときの人物の願い
- 行動または選択が起こる具体的理由
- 場面の最初と最後で変わるもの（感情、知識、関係、期待）
- 五感のうち有効なもの2つ程度
- 登場させる象徴と、その**物理的な役目**
- 読者に説明せず伝えること
- この場面固有の、平凡で具体的な細部

象徴や伏線を全場面に無理に詰め込まない。

### ② 小説家：第一稿の執筆

- 構成シートは参照するが、文章を箇条書きの翻訳にしない。
- 各少女が何を見て、何を見落とすかを大切にする。
- 世界設定を説明するより、人物がそこで生活する状況を書く。
- 小説のための立派な台詞を言わせるのではなく、その少女なら何を言うか考える。
- 結末の感情を解説する一文は、いったん外して成立するか検討する。

### ③ 文芸編集者：批評のみ

この段階では**全面改稿をしない**。指摘を具体化する。

- どの文が陳腐・説明過多・不自然なのかを引用して示す。
- その文がなぜ読書体験を損ねるのか述べる。
- 修正の優先度を高／中／低で示す。
- 会話の声が二人で交換可能になっていないかを確認する。
- 美しいが機能していない装飾や、意味の重複を探す。
- その場面の最もよい表現も挙げ、改稿で消さないようにする。

「文学的にして」「もっと美しく」などの抽象的な指摘で終わらない。

### ④ 推敲担当：目的を持った改稿

- 批評の優先順位に沿って修正する。
- **改稿A：最小修正**（語彙、文末、説明過多を調整）。
- **改稿B：大胆な再構成**（焦点、視線、会話順、段落を組み直す）。
- 二案を比べ、よい部分を統合する。書き換えによって原稿の自然さが失われたら元に戻す。
- 象徴が目立ちすぎたら、解説ではなく日常の行為へ戻す。

### ⑤ 最終審査：通し読みと採否

- この場面を初めて読む人が状況を理解できるか。
- 登場人物の魅力が**物語の都合から独立して**存在するか。
- 前の場面から因果と感情が自然につながるか。
- 読み返すと象徴の意味が増えるか。
- 説明や余計な比喩を削ったほうが強い文がないか。
- 結末を知っている作者だけが理解できる文章になっていないか。

作者が承認した版を正式な採用稿とする。

## 5. 幕ごとに文体の重心を変える

四幕は同一作品なので、文章の人格は保つ。しかし焦点やリズムは変化してよい。

| 幕 | 描写の重心 | 注意する失敗 |
| --- | --- | --- |
| 第一幕：陶酔 | 手触り、習慣、静かな親密さ、微細な発見 | 幸せを説明しすぎる／露骨に不穏さを匂わせる |
| 第二幕：倦怠 | 反復、時間の重み、ずれる会話と視線 | 「千年経った」だけで倦怠を処理する |
| 第三幕：崩壊 | **束縛する側の偏った視点**、認識の歪み、細部の食い違い | 加害者の解釈を客観的真実として書く／苦しみを単なる装飾にする |
| 第四幕：余韻 | 行動の小さな差、空白、両立する手がかり | 無根拠に曖昧にする／最後にすべてを説明する |

第三幕は特に「本人には確信があるのに、読者には矛盾が見える」文章を目指す。第四幕は「幸福の証拠」と「不穏の証拠」をともに残す。

## 6. 評価シート：点数より根拠

次の各観点を仮に1〜5段階で比較する。ただし客観的な文学得点ではない。点数の理由には**本文の引用**を付ける。

| 観点 | 確認すること |
| --- | --- |
| 自然さ | 不自然な言い回しや、情報を渡すための会話がないか |
| 人物の固有性 | 台詞・視線・行動を入れ替えると違和感が生じるか |
| 具体性 | 物の材質・光・体勢・間合いが意味を持つか |
| 説明と余白 | 明言すべきことを逃げず、説明不要なことを言いすぎないか |
| リズム | 文長・段落・沈黙の配置が場面に合うか |
| 象徴の自然さ | 髪・糸・花・目が生活の道具であり、同時に意味を帯びるか |
| 感情の説得力 | 感情の結果だけでなく、その変化を場面で経験できるか |
| 続きへの力 | 読み終えて、人物の次の選択を知りたくなるか |

**合格条件**：「総合点が高い」より「読者が引っかかる大きな欠点がない」「改稿で明確に改善した根拠がある」を重視する。

## 7. AIへの指示テンプレート

以下はGitHub上の原稿を扱う際の工程別プロンプト。人間と同様、どのモデルも万能ではない。

### 執筆

~~~text
あなたは『二人』の小説本文を担当する。
docs/PLOT.md と docs/METAPHORS.md と docs/STYLE.md を参照する。
今回の場面設計を満たして、自然な日本語の小説として執筆する。

優先すること：
- 人物固有の観察と行動
- 説明ではなく出来事から感情が伝わる描写
- 生活に根差した具体物と自然な会話
- 意味を説明しないメタファー
- 章内のリズムの変化

避けること：
- 予定されたテーマを人物に解説させる
- 毎段落に美しい比喩を入れる
- 「何より幸せだった」などの結論で感情を代弁しすぎる
- 表現を華麗にするためだけの不自然な語彙

今回の場面設計：
（ここに一場面の設計シートを入れる）
~~~

### 批評

~~~text
あなたは厳密な文芸編集者。
作者の意図を尊重しつつ、次の原稿を批評する。ここでは全文改稿しない。

1. 良い点を本文の引用付きで2〜3点。
2. 弱い文を最大5箇所引用し、弱さの理由と改善方針を指摘。
3. 会話・視点・リズム・描写・象徴・因果の問題を区別。
4. 最重要の修正を3つ優先順に列挙。
5. 読者が自然に受け取る印象と、作者が意図した印象のずれを指摘。

好みに基づく指摘と、明確な矛盾・不自然さを分ける。
~~~

### 推敲

~~~text
あなたは文章の推敲担当。
批評コメントと元原稿を参照し、構造と人物の意志を維持して改稿する。

- 元の良い箇所を守る。
- 説明過多、均質な台詞、不自然な比喩を優先的に修正する。
- 最小修正版と大胆な改稿版を分けて示す。
- 変更点と、その効果を短く説明する。
- 元原稿より弱くなった箇所があれば自己申告する。
~~~

## 8. 比較実験の手順

1. [第一幕の草稿](../drafts/futari_01.md)から一場面を選ぶ。
2. 原稿を保存したまま、最小修正版と大胆な再構成版を作成する。
3. 先に「どちらがAIによる新稿か」を明かさず比較する。
4. 具体的にどの表現が自然で、どれが作為的か記録する。
5. よかった改稿だけを採用し、docs/STYLE.md の方針を更新する。
6. 一場面で改善が確かめられてから、第二幕以降へ展開する。

ファイル運用例（実装時の案）：

- drafts/futari_01.md — 既存の第一幕草稿
- drafts/revisions/futari_01_minimal.md — 最小修正版
- drafts/revisions/futari_01_rewrite.md — 再構成版
- docs/STYLE.md — 文体方針と編集工程

※比較用ファイルは現時点で未作成。必要に応じて作成する。

## 9. API導入の判断基準

### まだ導入しない方がよい段階

- 「美しい文章」の合否条件が曖昧。
- 例となる採用稿／不採用稿が少ない。
- 一度の生成と推敲を分けるだけでも改善できる可能性がある。

### 導入する意味が出てくる段階

- 多数の場面へ同じ編集工程を繰り返したい。
- 複数の候補原稿と批評を保存・比較したい。
- GitHubの原稿・設計書・改稿記録を一つの自動ワークフローにしたい。
- モデルごとの出力を同条件で比較し、採用実績を残したい。

APIの価値は主に**制御・再現性・自動化**にある。「文章専用APIを呼べば文学性が保証される」とは考えない。モデル選択や使用可能機能は導入時に公式仕様を改めて確認する。

## 10. 守るべき原則

> **規則化するのは文章の形ではなく、文章を良くするための仕事の手順。**

テンプレート文の大量生産は避ける。作品固有の呼吸・余白・発見を優先し、推敲により元原稿の良さが失われる場合は戻す。

**次の実作課題**：第一幕の一場面を三案で比較し、作者が採用できる品質へ近づける。
